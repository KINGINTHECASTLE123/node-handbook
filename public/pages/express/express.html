Express

Creating an Express Server

Express is the most popular Node.js web application framework, designed for building web applications and APIs.

To use Express in your Node.js application, you first need to install it: 

npm install express

To create a server:

  1. Import Express from the library.
  2. Create an application using express()
  3. Start the server with app.listen()

Example:

import express from 'express';
const app = express();

app.listen(3000, () => {
  console.log("Server is running on port", 8080);
});

Client-Server Model

The client-server model describes how a client and a server communicate over a network:

  1. Client: Sends a request to the server.
  2. Server: Receives requests, processes them and sends responses.
  3. Request: The message sent from the client to the server.
  4. Response: The message sent back from the server to the client.

Example:

When you visit a website, your browser sends an HTTP request to the server. The server processes the request and returns an HTTP response containing the requested page and data from the server.

Serving HTML Files

Express can serve HTML files using res.sendFile(). The path.resolve() method creates a path to the file, so Express can locate it.

Example:

import express from 'express';
import path from 'path';

const app = express();

app.get('/', (req, res) => {
  res.sendFile(path.resolve('public/index.html'));
});

app.listen(8080, () => {
  console.log("Server is running on port", 8080);
});
  • app.get() handles GET request to /.
  • res.sendFile() sends the HTML file to the client.
  • path.resolve() creates a path to the file

Static Files with express.static()

Express can serve static files such as CSS, JS, images and HTML using the express.static() method.

By serving only the public folder, you avoid exposing other project files, such as .env and package.json, through this static file middleware.

Example:

import express from 'express';
import path from 'path';

const app = express();

app.use(express.static(path.resolve('public')));

app.listen(8080, () => {
  console.log("Server is running on port", 8080);
});
  • express.static makes the files in the public folder accessible to clients.
  • path.resolve creates an absolute path to the folder.
  • Clients can request files such as /style.css etc.

Client Files vs. Server Files

Client files are sent to the browser and run on the user's device. They include HTML, CSS and frontend JS.

Server files run on the server and handle requests, business logic and access to databases. They should not be sent directly to the client.

Example:

project/
├── public/          # Client files
│   ├── index.html
│   ├── style.css
│   └── script.js
├── app.js           # Server file
├── .env             # Sensitive configuration
└── package.json
  • Client: Users can access files served from public through their browser.
  • Server: app.js runs on the server and handles requests.
  • Security: We keep sensitive files outside public to avoid exposing them through static file serving.

Client-Side vs. Server-Side Redirection

Redirection sends a user from one URL to another. It can happen on the client or on the server.

Client-Side Redirection

The browser handles navigation using HTML or JS. There are three common approaches:

1. Anchor tag: Creates a link that takes the user to another URL when clicked. 

<a href="/">Go to homepage</a>

2. JavaScript: Redirects the browser immediately or after a delay. replace() does not keep the current page as a separate entry in browser history. 

setTimeout(() => {
  window.location.href = "/";
  // window.location.replace("/");
}, 3000);

3. Meta tag: Redirects the browser automatically after a specified number of seconds. 

<meta http-equiv="refresh" content="3; url=/">

Server-Side Redirection

The server redirects the browser by sending an HTTP response with a 3xx status code. Express uses 302 Found by default with res.redirect(). 

app.get('/old-page', (req, res) => {
  res.redirect('/new-page');
});

Key difference: Client-side is handled by the browser, while server-side is initiated by the server through an HTTP response.
