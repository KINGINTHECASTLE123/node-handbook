REST APIs

What is a REST API?

A REST API enables communication between client and server over HTTP. It exchanges data typically in JSON format using standard web protocols.

  1. Uses HTTP methods like GET, POST, PUT, PATCH, and DELETE.
  2. Client sends request to server endpoints (URLs).
  3. Server returns responses such as JSON, XML, HTML, or images.
  4. Maps HTTP methods to CRUD operations (Create, Read, Update, Delete).

Example:

GET /animals

This request asks the server to return a collection of animals.

REST Conventions

REST APIs follow conventions that make endpoints predictable and consistent.

Our three REST conventions:

  1. Use the correct HTTP method for the action.
  2. Follow a consistent order of methods.
  3. Use plural nouns for endpoints that represent collections.

Example: Animal API

HTTP method Endpoint Action
GET /animals Get all animals
GET /animals/{id} Get one animal
POST /animals Create an animal
PUT /animals/{id} Replace an animal
PATCH /animals/{id} Update part of an animal
DELETE /animals/{id} Delete an animal
  • HTTP method: Describes the action being performed.
  • Order: List resources first, then individual resources, followed by create, update and delete operations.
  • Plural nouns: Use /animals instead of /getAnimals or /animal.

These conventions help make APIs easier to understand and use.

Richardson Maturity Model

The Richardson Maturity Model describes how an API follows REST principles. It has four levels, from 0 to 3.

  1. Level 0 (The Swamp): One single URL for everything (e.g., sending all requests via POST to /api).
  2. Level 1 (Resources): Uses separate URLs for different resources, such as /animals and /animals/1.
  3. Level 2 (HTTP Methods): Uses the correct HTTP methods and status codes, such as GET, POST, PUT and DELETE.
  4. Level 3 (HATEOAS): The API response includes smart links guiding the client on what they can do next.

Our three REST conventions follow level 2 because we use resources, appropriate HTTP methods and HTTP status codes.

CRUD with Express

CRUD stands for Create, Read, Update, Delete. These are the four basic operations used to manage data.

In Express, CRUD operations can be implemented using routes and HTTP methods.

Example: GET an animal by ID

app.get('/animals/:id', (req, res) => {
  const animal = animals.find(
    (animal) => animal.id === Number(req.params.id)
  );

  if(!animal) {
    return res.status(404).send({ errorMessage: 'Animal not found'}); 
  }

  res.send({ data: animal });
});
  • req.params.id gets the ID from the URL.
  • find() searches for the animal.
  • 404 Not Found is returned if the animal does not exist.
  • res.send() sends the animal wrapped in a data object.

Example: POST a new animal

First, enable JSON request bodies:

app.use(express.json());

Then create a POST route:

app.post('/animals', (req, res) => {
  const animal = req.body;

  res.status(201).send({ data: animal });
});
  1. express.json() allows Express to read JSON data from the request body.
  2. req.body contains the submitted data.
  3. 201 Created indicates that a resource was created.

The POST example returns the submitted data but does not save it. A real implementation should store the new animal.

HTTP Status Codes

HTTP status codes describe the result of a request.

Range Meaning Example
2xx Success 200 OK
3xx Redirection 301 Moved Permanently
4xx Client error 404 Not Found
5xx Server error 500 Internal Server Error

Sending Data to the Server

1. Path Parameters

Path parameters identify a specific resource in the URL.

Example URL:

GET /animals/1

Express:

app.get('/animals/:id', (req, res) => {
  console.log(req.params.id);
});
  • req.params contains the values from the route parameters.
  • Here, req.params.id is "1"

2. Query Parameters

Query parameters provide additional information through the URL, such as filters or sorting options.

Example URL:

GET /animals?sort=name

Express:

app.get('/animals', (req, res) => {
  console.log(req.query.sort);
});
  • req.query contains the query parameters.
  • Here, req.query.sort is "name".

3. Request Body

The request body sends data to the server, commonly when creating or updating resources with POST or PATCH.

Example JSON body:

{
  "name": "Frida",
  "species": "Dachshund"
}

Example:

app.use(express.json());

app.post('/animals', (req, res) => {
  console.log(req.body.name);
});
  • req.body contains the submitted data.
  • express.json() is required to parse incoming JSON request bodies.

Key difference: req.params gets data from the path, req.query gets data from the query string, and req.body gets data from the request body.

Anatomy of a URL

A URL contains several parts that help identify a resource and how to access it.

Example URL:

https://www.example.com:8080/animals/1?sort=name#top
Part Value Purpose
Protocol https:// Defines the communication protocol
Subdomain www Identifies a subdomain
Domain name example.com Identifies the domain
Top-level domain (TLD) .com The final part of the domain
Port 8080 Identifies the server port
Path /animals/1 Identifies the requested resource
Query string ?sort=name Provides additional parameters
Fragment #top Points to a section within the page

Important: The query string can be accessed through req.query in Express. The fragment is handled by the browser and is not sent to the server in the HTTP request.

Testing with Postman

Postman is a tool for testing APIs by sending HTTP requests and inspecting responses.

You can use it to test GET, POST, PUT, PATCH and DELETE requests, including responses.
