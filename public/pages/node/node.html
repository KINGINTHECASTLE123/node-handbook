Node.js & npm

What is Node.js

Node.js is an open-source, cross-platform JavaScript runtime that allows JavaScript to run outside the browser, for example, on a server.

How to Run Files:

  1. Create a JavaScript file, e.g. app.js
  2. Open the terminal in the file's folder.
  3. Run the command:
node app.js

npm (Node Package Manager)

npm is the default package manager for Node.js. It is used to install and manage packages and dependencies in a project.

Example:

npm install express

npm is included with Node.js, while Yarn and pnpm are alternatives:

  • npm: The default package manager for Node.js.
  • Yarn: An alternative with its own commands and features.
  • pnpm: Saves disk space by sharing packages between projects.

package.json

The package.json file explains project metadata, dependencies, and scripts. The file can be written manually or generated using npm init.

The npm init command creates a package.json file. It asks for project information such as name, version, description and entry point: 

npm init

The node_modules folder contains the packages installed in the project. It should not be pushed to Git because it can be created again by running npm install using the dependencies listed in package.json.

npm Scripts

npm scripts are commands you can define in the scripts section in the package.json file. They allow you to run tasks using npm run.

Example:

"scripts": {
  "start": "node app.js"
}

Run the script:

npm run start

This executes node app.js

Nodemon

Nodemon automatically restarts the Node.js application when changes are detected or saved. It is used only during development, not in production because the server would reset all the time.

Install it as a development dependency:

npm install --save-dev nodemon

The ext option specifies which file extensions Nodemon should watch for changes.

Example in my nodemon.json file:

{
  "ext": "js,mjs,cjs,json,css,html"
}

This restarts the application when .js, .json, .css and .html files change.

CommonJS vs. ES Modules

Node.js supports two module systems:

CommonJS (how it would look):

// export
module.exports = { constructPage };

// import
const express = require("express");
const { constructPage } = require("./templatingEngine.js");

ES Modules (used in this project):

// export
export function constructPage() {}

// import
import express from "express";
import { constructPage } from "./templatingEngine.js";

Advantages of ES Modules:

  • Standard: ES Modules are the official JavaScript standard, while CommonJS is Node.js older module system.
  • Same syntax: import and export work in both browser and Node.js.
  • Static analysis: Tools like VSCode can better detect errors and suggest code.
  • Tree shaking: Build tools can remove unused code to make bundles smaller.
  • Top-level await: Lets you use await without wrapping it in an async function.

To use ES Modules in Node.js, add "type": "module" to package.json.

Environment Variables

Environment variables store settings outside your code, such as API keys, passwords, ports etc. You can define them in a .env file: 

PORT=8080

Load the file when running your application:

node --env-file=.env app.js

Access the variable in Node.js using process.env.PORT.

Add .env to .gitignore to prevent sensitive information from being pushed to Git. Create a .env.example file to show developers which variables they need to configure.
